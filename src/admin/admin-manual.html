GOD MODE GUIDE

管理员操作手册

管理员端现在就是一个权限更高的游玩面板：地图、工具、运营和玩家看到的完全一致，右侧城市控制台负责修改章节、关卡及关卡内定义。所有修改先进入草稿预览，明确发布前不会写入磁盘。

工作流章节关卡参考答案世界编辑路线建筑多日任务发布

统一工作流

  1. 在上方按普通玩家方式观察、规划道路并运行城市；运营时顶部实时满意度及地图居民表情会标出因排队或在途过久而不满的客流。
  2. 在右侧连续修改关卡参数。输入框、路线和建筑参数只更新草稿，不会在每次离开输入框时重建游戏，因此当前路线、焦点、展开区和滚动位置保持不变。
  3. 完成一组修改后点击“应用草稿到预览”，一次性重建当前城市并查看玩家实际体验；新增、删除、地图编辑等结构操作仍会立即同步，以保持编辑对象一致。
  4. 用撤销、重做调整草稿；状态栏会持续进行服务器端结构校验。
  5. 确认后点击“保存并发布”。发布写入 levels.json 和 levels.local/。
  6. 点击面板底部“重启游戏服务”，状态栏确认服务恢复运行后，公开游戏即可加载新关卡。

重建预览会清空当前运行和未捕获的玩家路网。要保留上方规划，请先点击“将当前玩家路网设为初始道路”。

章节与关卡

  • 控制台可新建、编辑和删除空章节；章节 ID 只能包含小写字母、数字和连字符。
  • 关卡可新建、复制、删除和调整同章顺序。关卡顺序就是玩家看到的顺序。
  • 关卡信息包含名称、标题、任务说明、提示、预算、时长、公交上限、星级目标和功能开关；可连续修改多项，再统一应用到玩家预览。
  • 星级挑战中的通关星由完成运输目标自动判定；管理员配置满意度星阈值，以及效率星同时要求的最高建设点数和最大住宅排队人数。普通关卡使用关卡目标，多日任务还可逐日覆盖。
  • 至少必须保留一个章节和一个关卡，每关至少保留一条完整路线。

教程参考答案

  • 已有答案时可点击“加载参考答案到地图”，用完整答案替换上方玩家规划，随后直接运营、调整或重新保存。
  • 多日任务选择日期后，点击“按答案推进到所选日期”会从第 1 天开始确定性运行全部前序答案，以真实送达、满意度、收入、预算和建筑解锁状态进入目标日期；目标日尚无答案时可在继承的路网上继续规划并保存。
  • “自动验证完整答案链”会依次载入并运行每天答案，任一天缺少答案、预算不符或无法通关都会报告首个失败日期。发布和覆盖配置也会执行同样门禁。
  • 先使用上方玩家工具完成并验证教程关卡的方案，再点击“保存当前完整设计为参考答案”。
  • 参考答案保存道路、显式连接、等级、汽车引导、信号灯和公交线路；它不同于只保存初始路面的“将当前玩家路网设为初始道路”。
  • 公交线路上限至少为 2 时可设计换乘：两条线路必须在同一道路格都启用站点。乘客最多换乘一次，按班距和车程选择预计总时间较短的方案，并在首次上车时预约最终目的地容量。
  • 玩家首次失败后才会看到“查看参考答案”，多日任务按日期独立解锁；载入后仍停留在规划阶段，不会自动运营，也不会改写累计进度、收入或预算。实际预算不足时会拒绝载入。
  • 多日任务在每个 campaign.days[] 内保存当天的完整累计设计，但这些答案组成连续链：第 n+1 天必须建立在前 n 天答案的真实结算结果上。修改地图、建筑、预算、条件或较早日期答案后，应重新自动验证整条链。

地图与初始道路

  • 先用玩家工具栏切换“选择”，点击单格或拖出矩形；控制台会显示所选格子。
  • “空地 / 水面 / 桥梁 / 树木”批量修改选区。建筑格不能直接覆盖为地形；应先移动建筑。
  • 道路使用玩家的拖拽、剪刀、升级和降级工具编辑，因此操作结果与真实游戏完全一致。
  • 道路完成后必须点击“将当前玩家路网设为初始道路”，将道路格等级和显式连接分别写入 initialRoads 与 initialEdges。汽车引导、信号配置和公交线路属于玩家方案，不会成为关卡初始定义。

路线与建筑

  • 每条路线可设置名称、主色和浅色，并包含多个住宅和目的地。
  • 住宅配置格子索引、居民产生率和总人口；目的地配置标签和可选输入上限。
  • 可在建筑卡片直接填写格子索引，也可先选地图格，再点击“移动到地图所选首格”。
  • 删除建筑或整条路线时，控制台会同步清除原建筑格残留的初始道路出口；移动建筑还会清除目标格的初始道路、相关连接及冲突地形，避免草稿预览因悬空连接失败。已有参考答案不会自动改写，建筑调整后应重新验证并保存答案。
  • 目的地总接收能力必须覆盖同路线住宅总人口，建筑不能重叠、越界或位于水面和树木上。

玩家规划提示

玩家任务面板会持续列出不可达住宅、目的地容量、公交有效性和手动灯序冲突等问题，并以地图 ! 和定位按钮提示。若住宅没有可用直达或换乘公交，居民产生率又高于有效汽车出口相邻道路的自由流估算（道路速度 × 车道数之和），会提示出口积压风险；只计入显式连接且能通往同色目的地的道路，估算不保证实际畅通，也不校验公交运力是否充足。调整产生率时可在玩家预览中观察。

道路与公交总花费超过配置的效率星最高建设点数时，预算旁会显示超出点数；普通关卡用本关目标，多日任务优先用当日覆盖，沙盒不提示。降低花费后自动消失，不额外限制运营，原有手动灯序冲突仍需修正。地图提示及预算提醒不替代完整试玩验证。

多日任务

  • 启用后可设置 2～30 天的时长、最高收入和逐日星级目标；第 1 天时长同时作为关卡基础时长。
  • 每一天在全部居民送达后立即提前结算；若未全部送达，则运行到当日时限结束后结算。
  • 路线与建筑编辑的是全部潜在建筑，草稿会同步生成第 1 天基础路线。
  • 展开每栋建筑的“解锁与升级”，可按日期、累计送达、累计收入和上一日满意度设置联合条件，并添加住宅人口/产生率或目的地输入上限的升级阶段。

草稿、校验与发布

  • 右侧橙点表示存在未发布草稿；绿色校验提示表示可发布。校验失败时会一次列出发现的问题，点击问题可切换到对应关卡，并在带坐标时选中地图格。
  • 撤销与重做覆盖章节、关卡、参数、建筑和地形修改，最多保留 60 步。
  • 修改任一关卡后，先点击“验证并试玩”；结构校验通过后控制台会收起，必须用当前草稿实际通关。多日任务须完成最后一天。每个修改过的关卡都通过后，才可发布整份配置。
  • 试玩认证绑定当前关卡的完整版本。通关后只要继续修改该关，认证就会立即失效并重新阻止发布；撤销回已经通关的完全相同版本时，认证会恢复。
  • 连续编辑普通参数时，“应用草稿到预览”按钮会提示存在尚未同步的修改；点击后才统一重建游戏预览。验证试玩会自动应用最新草稿。
  • “放弃草稿并重新载入”会恢复磁盘版本。“保存并发布”只在完整校验和人工通关门禁均通过后写盘。
  • 游戏服务启动时会将静态资源读入内存，因此发布后点击面板底部“重启游戏服务”才能让公开玩家看到更新。按钮只重启并检查当前用户的 traffic-game.service，不会保存草稿；失败原因会显示在状态栏。

安全提醒：管理员服务默认仅监听 127.0.0.1，并会对连续失败登录短期封禁。对外开放必须显式设置 ADMIN_HOST、使用强密码并通过反向代理提供 HTTPS；代理终止 TLS 时同时设置 ADMIN_SECURE_COOKIE=1。
