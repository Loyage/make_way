# 慢行小城 · Make Way

原生 HTML / CSS / JavaScript 交通规划小游戏。3 个玩家教学章节下包含 17 个循序渐进且可自由选择的关卡，每章最后均为连续五日挑战；另有仅管理员可见的设计素材库。无构建步骤、无第三方依赖、无外部字体或图片请求。

## 本机游玩与网络访问

关卡从独立 JSON 文件加载，因此不能直接通过 `file://` 双击 `src/game/index.html`。需要 Node.js 18+，在项目目录启动本地服务：

```sh
node server.js
```

默认监听所有 IPv4 / IPv6 网卡的 **8180** 端口：

- 本机：<http://127.0.0.1:8180>
- 远程：`http://服务器IPv4:8180`
- IPv6：`http://[服务器IPv6]:8180`

自定义监听地址和端口：`HOST=0.0.0.0 PORT=9000 node server.js`。

**远程访问还需要防火墙放行、可路由的 IP，以及可能的路由器端口转发。监听所有网卡不等于已经可以从互联网访问。**

持久用户服务安装：

```sh
bash deploy/install-service.sh
```

详见 **[部署与网络说明](deploy/README.md)**。服务只开放游戏静态资源，不公开项目目录。各玩家在自己的浏览器内独立运行游戏，不共享道路、车辆或关卡状态；不是多人同步联机。

## 管理员面板

管理员面板采用与玩家端相同的地图、规划工具和运营界面，并在右侧增加“城市控制台”。管理员可在真实游玩视图中创建、排序和修改章节与关卡，编辑任务参数、功能开关、路线、建筑和地形；玩家工具绘制的路网可一键写为关卡初始道路。修改先进入可撤销的本地草稿并立即重建预览；每个修改过的关卡都必须通过服务器校验并由管理员实际试玩通关，之后“保存并发布”才会写入磁盘。发布后可直接点击面板底部的“重启游戏服务”，让公开游戏加载最新文件。

项目附带的管理员服务**需要密码**，将已发布配置持久化为 `levels.json` 清单和 `levels.local/` 分关文件。面板默认仅绑定 `127.0.0.1` 的 **8080** 端口，凭密码进入，未登录无法读取关卡或启动编辑预览；远程使用时须显式设置 `ADMIN_HOST`。

直接启动：

```sh
ADMIN_PASSWORD=你的密码 node admin-server.js
```

然后访问 <http://127.0.0.1:8080>。服务没有内置默认密码；未通过 `ADMIN_PASSWORD` 或 `PI_ADMIN_PASSWORD` 显式设置密码时会拒绝启动。安装脚本可从项目根目录 `.env` 读取密码，并会拒绝空值或弱默认值 `admin`。面板使用恒定时间比较校验密码，并按来源限制连续失败登录（5 次后短期封禁），未登录无法读写。远程使用可设置 `ADMIN_HOST=::`，但应先通过反向代理提供 HTTPS，并设置 `ADMIN_SECURE_COOKIE=1` 让会话 Cookie 仅通过 HTTPS 发送。

安装为持久用户服务（会读取 `ADMIN_PASSWORD` 或 `.env` 中的密码）：

```sh
bash deploy/install-admin-service.sh
```

面板支持：新建、编辑和删除空章节，在章节下新建 / 复制 / 删除关卡、把关卡移动到其他章节，或用 ↑ / ↓ 按钮调整关卡在章节内的顺序（顺序即游戏内的第几课）；还可编辑关卡元数据、预算、时长与功能开关（含公交线路），增删路线（每条路线可含多个住宅与目的地，各自带居民产生率、总人口与可选输入上限），以及在地图上绘制水面、桥梁、树木、建筑和初始道路。每关地图宽高可分别设为 8～64 格；调整已有地图时内容保持相对中心位置，越界地形和道路会裁剪（会裁掉建筑时拒绝调整）。建筑坐标用两个数字表示：地图中心为原点 (0,0)，向右为 +x、向上为 +y。启用「多日任务」后，可设置 2～30 天并逐日编辑运营时长、最高收入与星级目标；路线和潜在建筑只配置一次，每栋住宅或工作单位可按最早日期、累计送达、累计收入和上一日满意度解锁，并可添加多个条件升级阶段；还可从地图任意选区创建扩建区域，设置联合开放条件和建设点费用。玩家端进入关卡或新一天时会自动聚焦当前已开放的道路与建筑；未来区域覆盖保留隐约轮廓的半透明灰雾并显示可点击锁，达成任务后仍须点击锁或灰雾区域并支付建设点，之后建筑才继续检查自身条件；同色住宅与目的地没有成对启用时，其人口或容量保持锁定，不进入运输目标与满意度。包含关卡的章节必须先移空才能删除。保存会把每关分别写入 `levels.local/<章节>/`，项目根目录的 `levels.json` 只保存章节清单路径；「另存为配置」会以单文件快照写入 `level-presets/`（不能重名），「覆盖默认配置」会重建 `levels/` 并更新 `built-in-levels.json` 清单。

参考答案可由管理员直接加载到上方地图，用于立即运营测试、继续调整和重新保存。多日任务可按前序答案自动运行到所选日期，并以真实送达、满意度、收入、预算和解锁结果继续创建当天答案；完整答案链可一键自动验证，发布时也会拒绝缺失、预算不符或无法通关的答案链。为方便一次调整多个参数，普通输入框、路线和建筑参数先只更新草稿，不会在每次离开输入框时重建游戏预览；完成一组修改后点击「应用草稿到预览」统一同步，当前路线、输入焦点、展开区和滚动位置不会被反复重置。新增、删除和地图编辑等结构操作仍会立即同步。编辑器还提供最多 60 步撤销 / 重做（`Ctrl/Command + Z`、`Ctrl/Command + Shift + Z`）、一次列出多项问题且可定位到关卡或地图格的全配置自动校验，以及按中心坐标整体平移地图内容。整体平移会同时移动地形、初始道路和多日任务的全部潜在建筑，任何内容越界时整次操作都会取消。地图下方的「初始道路仿真」直接使用游戏的 `core.js` 引擎，可按当前日期以 1× / 2× / 4× / 0.5× 运行，观察送达量、时间、在途车辆和住宅等待人数；仿真只测试关卡中预铺的初始道路，不修改关卡数据，开始编辑时会自动停止。

**重要**：游戏服务在启动时把静态资源读入内存，因此修改 `levels.json` 后需重启游戏服务才能生效。管理员登录后可点击面板底部的“重启游戏服务”；它只会执行并检查当前用户的 `traffic-game.service`。也可在终端执行：

```sh
systemctl --user restart traffic-game.service
```

`built-in-levels.json` 是默认关卡总清单，只保存 `levels/<章节>/chapter.json` 路径；章节清单再保存本章各关 JSON 的相对路径，每一关独立存放。`levels.json` 存在且合法时游戏自动优先加载它，管理员生成的具体关卡位于 `levels.local/`，二者均被 `.gitignore` 忽略。关卡 v2 用 `initialRoads: [{cell, grade}]` 保存路面等级、用 `initialEdges: [[a,b]]` 保存显式连接；加载器会把旧版 `[a,b,grade]` 自动迁移。加载器仍兼容旧版扁平数组和旧版整库 JSON。

## 三章十七关渐进式小城

- **第一章「道路入门」5 课**：基础连接、拆除、道路等级、剪断，最后以「五日新城」串联道路建设工具。
- **第二章「路口调度」7 课**：2.1 认识 T 形与十字路口的无灯自动避让；2.2 在「林间环城」接短支线、借既有环路疏导；2.3 用四向车流理解自动红绿灯；2.4 按预计车流生成灯序并去掉空放方向；2.5 为不对称流量分别设置各阶段 2 / 4 / 6 秒绿灯；2.6 以多起点、多目的地和多个受控路口分流；2.7 完成「五日路口值守」。
- **第三章「公共交通」5 课**：3.1 只用一条公交线体验批量运输；3.2 用环线连续服务多组通勤；3.3 在唯一跨河桥头同站换乘；3.4 用汽车禁行或不连接建筑出口强制公交通勤；3.5 完成「五日公交网」。

各章关卡仍可自由选择，但功能按教学顺序开放：第二章前两课不开红绿灯，2.3 起开放信号设置；公交直到第三章才开放。三项多日挑战都会继承前一天的设计、预算、区域开放和建设进度，并逐日增加客流或新地点；每次进入关卡或新一天会自动聚焦当前已开放的道路与建筑，未来区域以半透明灰雾和可点击锁标示且不可建设，满足任务后由玩家付费开放。

旧「城市调度」中未纳入新教学线的都会早高峰、交叉调度、多点通勤、环线通勤和同站换乘已移入 **「设计素材库」**。该章节带 `hidden: true`，玩家关卡选择与前后关导航不会显示或进入，管理员控制台仍可选择、试玩和改造这些素材；章节下拉框会标注“仅管理员”。章节隐藏属性会随拆分清单发布和回读。

### 持续规划提示

- 任务面板显示规划问题数量，展开查看说明并定位；地图小 `!` 标出不可达住宅、容量不足、无效公交和信号冲突，悬停或选择可看简短说明。
- 没有可用直达／换乘公交的住宅，若居民产生率高于有效出口相邻道路的自由流估算（速度 × 车道数之和），提示出口积压风险；只计入显式连接且能通往同色目的地的道路，不把车辆容量当成吞吐量，也不保证实际畅通或公交运力充足。
- 道路与公交花费超过本关／当日效率星点数上限时，预算旁显示超出点数，退款达标后消失；沙盒不提示。不会额外阻止运营，原有冲突灯序仍须修正，得星仍需满足其他条件。
- 提示随规划编辑、撤销和载入刷新，复用运营前可达性与公交检查，不在每个动画帧重复寻路。

### 运营前判断客流压力

地图每个住宅下方直接显示该住宅的居民产生率，每个目的地标注其输入上限（不设上限则不显示）；侧栏提供完整的需求清单，含每个住宅与目的地的坐标、总人口、产生率和输入容量。路线不再局限于“一点到一点”：一条路线可以包含多个住宅（各自拥有产生率和总人数）与多个目的地（各自拥有可选输入上限）。车辆从某住宅出发后，按“可到达且输入未满的最近目的地”就近选择并锁定该目的地，途中再随路网重新寻路但不再变更目的地；某目的地达到输入上限后，后续车辆改派到次近的可达目的地。小房子为 **1 人/s**，大房子为 **4 人/s**，高层为 **6 人/s**，外形随规模变化。每辆小汽车代表 1 位乘客；公交车可搭载多人。总人数包含尚未出发、排队、在途和已抵达者，不是当前队列长度。住宅角标仍表示当前排队人数。

以游戏实际使用的 `step(0.05)` 测量 13 格无路口单向直线，在持续饱和输入下，剔除前 30 秒启动期后，支路／干道／快速路的稳定抵达量约为 **2／5／6.67 人/s**。这是本模拟的实测值，不是速度乘容量，也不是含路口道路的保证值。小房子适合支路，大房子适合干道，高层适合快速路；合流、转弯、低等级出入口和信号配时都可能降低通达效率。测试同时验证持续 55 秒的高层需求无法由独立干道全部运完，更不能靠最低级道路完美运输。

居民从运营开始按住宅的产生率逐步进入队列，达到标注总人数后停止新增。汽车没有独立的住宅出口速率：驶出速度只取决于门口第一格道路的等级，并受该格车道位置是否可用限制。公交到站可集中接走已经产生并排队的居民，但不能提前接走尚未产生者，且与小汽车共享住宅总人口。暂停冻结需求；停止运营或读取设计后重置需求与统计。关卡目标自动取所有住宅人口之和；满意度将已产生但未抵达者按最低档计入，但不影响胜负。

## 道路等级、容量与信号灯

| 等级 | 每格建设费用 | 速度（格/秒） | 每方向车道数 | 路口前转向分工 | 每方向容量（辆） |
| --- | ---: | ---: | ---: | --- | ---: |
| 支路 | 1 点 | 2.8 | 1 | 左转、直行、右转混行 | 2 |
| 干道 | 2 点 | 4 | 2 | 左转专用；直行与右转混行 | 4 |
| 快速路 | 3 点 | 5.2 | 3 | 左转、直行、右转各自专用 | 6 |

路面宽度随车道数增加，所有等级的车辆长宽一致，不再缩小车辆以塞入更多车道。每格每条车道有前后两个位置，后车先进入后位，前位空闲才可前进；移动期间保留源位置和目标位置预约，禁止穿过前车。因此双向各一车道的支路每格共容纳 4 辆，干道与快速路双向总容量依次为 8、12 辆。

- 地图默认进入**观察模式（1）**：电脑端拖动地图，普通滚轮滚动页面，按住 Ctrl 滚动或触控板双指捏合缩放；手机端单指拖动、双指缩放，越过边界松手后会回弹。拖拽从已有道路起步时会继承起点等级：经过空地会按该等级新建道路，经过不同等级道路会用箭头和状态提示预览升/降级，松手后把整段统一到起点等级；只有从建筑或空地起步时才建设支路并保留已有道路等级。沿预览路线回拖可逐段取消，松手时整条规划才原子应用。相邻路面、建筑出口、桥梁与岸边仍须明确拖过。
- **剪刀（4）**沿道路拖动，剪断经过的格间连接，保留两侧路面与等级，不返还预算；再沿断口拖动修路即可接回。
- 在选择模式点击非路口道路可进一步选中两端路口之间的连续路段（不含路口格，避免影响其他岔路），再对整段升级、降级或拆除；操作会先显示预计格数和预算变化，确认后才施工。矩形区域和整段路线都在地图右下角提供只有 ↑ / ↓ / ⌫ 图标的快捷按钮，下方仍保留带文字操作。每次升降一个等级；升级支付差价，降级返还差价，拆除返还全部费用。
- 点击开始运营时会先执行检查，列出不可达住宅、同色目的地容量不足、公交闭环/站点/站序问题，以及按当前连接与容量计算的理论送达上限；这些提示可忽略并按现状运行，无效公交线路不会发车。手动红绿灯的冲突组合属于必须修正的设计问题：检查会显示路口坐标并提供地图定位，修正或改用自动信号前不能运营。运营开始后规划会锁定，暂停时也只能选择区域查看路况；停止运营后才可继续建设、升降级、拆除、剪断或调整信号灯。
- 玩家界面提供最多 60 步规划撤销 / 重做，覆盖道路建设与拆除、剪断、批量升降级、信号设置和公交编辑；可使用界面按钮，或按 `Ctrl/Command + Z` 撤销、`Ctrl/Command + Shift + Z` / `Ctrl/Command + Y` 重做。切关、重置、读取设计和进入新的五日任务日期会清空历史；运营期间按钮锁定，停止运营后仍可继续撤销。
- 容量统计包含当前车辆和驶入预约；满载时车辆在上游等待，住宅也可能积压。各方向分别限额，并为同向车辆分配不同通行位置。不会因为拥堵直接判负，但排队会影响在时限内运送全部居民。
- 道路速度在混合等级交界处取较慢的一侧。小汽车按自由流预计耗时寻路，会选择稍长但更快的路线；实时拥堵不进入路线成本。选择道路可设置「偏好」或「汽车禁行」主动引导分流，公交仍按固定线路通行。
- 三岔与十字路口依据实际连接数识别（建筑出入口也计入分支），可独立配置控制方式。关闭红绿灯时，可选择按到达时间**自动让行**，或排列北、东、南、西入口的通行优先级；两种方式都逐车通行，进入与驶离路口时按正常道路速度的 **35%** 行驶。开启红绿灯后，十字路口自动循环横向直行、横向左转、纵向直行、纵向左转；T 形路口则自动识别贯通主路，使用“主路双向直行、主路转入支路、支路汇入主路”三阶段灯序，不为空缺入口分配绿灯。也可配置 1～8 个手动阶段，自由组合直行与左转动作并调整阶段顺序；编辑时允许暂存冲突组合并以红色标出，便于继续调整，但修正前不能开始运营。每阶段可设为 2、4 或 6 秒，之后含 0.25 秒全红清空。右转始终让行，出口满载时所有方向都不能进入路口；规划和暂停时信号计时停止。
- 车辆会在驶近路口时按道路等级进入转向车道：支路三种转向全部混行；干道左转独占一条车道，直行与右转共用另一条；快速路的左转、直行、右转各有专用车道。红灯前等待的直行车会阻塞支路和干道同车道中的右转车，但快速路右转车可从专用车道通过，因此高级道路能更快疏解路口队列。
- 按车辆进入及离开路口的方向判断转向。**右转不受灯色限制**，但须避让可通行的直行/左转车辆及已经预约冲突区域的车辆；出口满载时仍等待。清空期也允许没有冲突的右转。
- 在规划阶段选择道路即可查看容量；选择路口可调整控制方式与绿灯时长。手动灯序卡可直接在地图预览本阶段动作，冲突提示会列出具体动作，「按车流建议」根据预计住宅路径生成安全灯序。结算按入口展示平均等待和最大队列。
- 路口改为**四分区冲突预约**，不再整格仅限一车：对向直行、对向受保护左转及不冲突的右转可以并行。关闭信号灯则恢复 35% 速度、单车通行的自动避让。路口是通行空间，不按普通路段的前后车位排队；升级道路不会取消冲突约束。这是保守的简化冲突模型，不模拟全部真实车道转向组合。
- 「显示道路负荷」为道路加上绿 / 橙 / 红色边框，代表最忙方向的低负荷 / 接近满载 / 已满；路口显示四个冲突分区的预约率。红框不一定代表持续拥堵。路口不再使用小灯和文字标牌，而是在方格各进口一侧印上箭头线：直行与左转分别用绿线表示放行、红线表示等待；右转始终使用浅色弯箭头表示让行通行。只绘制实际存在的入口和出口，关闭信号后全部箭头变为浅色。车辆绘制在箭头线上方，侧栏仍提供完整阶段及倒计时说明。
- 所有玩家关卡及管理员素材均有预算内通关方案；参考方案按路线显式连接，并在教学要求的路口配置自动或手动信号。三章的五日挑战另测试收入、付费扩建、单边建筑数值锁定、工地推进和检查点回溯。
- 设计存档使用 v8 格式，保存道路、连接、汽车道路引导、完整路口控制方案，以及公交线路的车辆、发车间隔、双向停站等设置；v1～v7 存档继续兼容迁移。

## 公交线路

第三章开放 **公交线（5）** 工具，并从单线运营逐步教授环线多站、桥头同站换乘和公交强制通勤。线路沿已有连接分段续画。普通线路须闭环；开放线路可开启原路返回，并可选择返程是否停站。每条线路配置 1～3 辆车和 2 / 4 / 6 / 8 秒发车间隔，多辆车从起点依次投入。3.1、3.2 限制一条线路，3.3 起允许两条线路在共同启用的同一道路站格换乘。线路道路与连接受保护，可从末端反向擦除、清空或删除后再修改道路。

每条线路可配置 **1～3 辆**公交车，每辆消耗 **6 点**建设预算，删除线路会返还车辆预算。公交容量为 **12 人**，按当前道路小汽车速度的 **1.35 倍**行驶，并与小汽车共享车道位置、路口冲突区和信号规则。公交车身跟随所属线路颜色，并以黄色车头和「BUS」字样与小汽车区分；车顶黄色气泡实时显示“车上人数 / 12”。线路沿行驶方向靠道路右侧连续绘制，并用稀疏小箭头提示方向，使往返路径分居道路两侧；玩家绘制段为实线，系统自动生成的原路返程段为同色虚线。公交面板为每条线路提供眼睛开关：关闭后线路不会完全消失，而会低饱和、低透明度虚化，便于聚焦重合线路。线路彩线、道路黄点和建筑“站”标识分别表示线路、站点和可服务建筑。

绘制完成后，紧邻建筑的线路道路格会自动成为站点，不要求另建建筑出口连接；选中线路道路格可管理站点。两线在同一道路格都启用站点时形成换乘站，每名居民最多换乘一次。规划阶段按半个班距和静态车程选择预计较快的直达或换乘方案；运营阶段改按最近可服务车辆的位置估算等待，并加入沿线拥堵、信号、预计停站及满载班次成本。候车方案只有明显更快时才换线，已经上车的居民锁定剩余行程。第一次上车即预约最终同色目的地容量；换乘候车计入公交在途和完整通勤时间。规划阶段显示分配到线路的预计客流及可换乘线路，运营阶段显示住宅/换乘候车、上下车和最大候车；结算列出每线平均载客率、满载拒载、换入/换出、上下车与周转数，并汇总换乘人次和等待表现。公交每站先下后上，上下客合计 **8 人/s**，不能提前接走尚未产生的居民。

这是离散格子交通模型；“快速路”是游戏中的道路等级，并非真实交通法规中的封闭快速路。

## 操作

操作方法、车辆出行与交通模拟规则详见 **[游戏指南](src/game/manual.html)**。

- **观察模式（1）**：拖动地图，使用 Ctrl + 滚轮或触控板/触摸双指缩放，不会选择格子或施工。
- **选择模式（2）**：点击选择单格，拖动选择矩形区域；非路口道路可扩展选中到两端路口（不含路口格）。区域与路线提供 ↑ / ↓ / ⌫ 图标快捷操作，整段路线施工前还会显示预计结果并要求确认。住宅显示人口守恒与预计路径，接收建筑显示容量信息，空地可建设单格支路。
- **拖拽模式（3）**：从道路起步时以起点等级新建空地道路并改造经过的不同等级道路，用 ＋ / ↑ / ↓ 和文字实时预告结果；只有从建筑或空地起步时才建设支路、保留已有道路等级。回拖取消当前预览，松手才一次性应用。
- **剪刀模式（4）**：剪断经过的道路连接，但保留路面与等级，不返还预算。
- **公交线模式（5）**：沿已有连接分段绘制公交线路，每次从当前末端续画；普通线路须闭环，或开启原路返回后使用开放线路。可配置 1～3 辆公交；仅在开放公交功能的关卡可用。
- 拖动经过的上下左右格间才相连，建筑也必须拖动连接。河流只能经过桥梁格，但桥面道路需要玩家建设，树林不可建设。
- 点击「开始运营」后，住宅按产生率生成有限人数；汽车在门口道路出现可用位置时逐辆驶出。多住宅/多目的地路线中，每辆车先选择自由流预计耗时最低的可达目的地与路线，并遵守玩家设置的偏好/禁行道路；运营中会按道路负载、受阻、路口等待和信号周期每秒重估路线，仅在新路线至少节省约 18% 动态成本时改道，避免来回摆动。
- 在本关时限内将全部住宅居民运抵目的地即胜利。规划时，住宅右上角显示总人口、目的地右上角显示总容量；运营时分别实时显示尚未离开住宅的人数与扣除已分配乘客后的剩余容量。住宅左下角显示居民产生率，右下角“待”字气泡显示排队。顶部会按已经产生居民的当前完整通勤时长实时计算满意度；跨过 8、15、25 秒时逐档下降，地图在长时间排队的住宅、汽车、公交及换乘站旁用居民表情和人数提示不满来源。
- 结算报告按已抵达居民从产生到到达的完整通勤时间分为轻松、舒适、尚可和漫长四档，已产生但未抵达者按最低档计入满意度；平均通勤和 P95 只统计已抵达者。报告另展示人口守恒、各路线送达率、最大住宅排队、动态改道次数、前三道路热点、公交与路口表现，并按关卡在浏览器中记录满意度、P95 和建设点数个人最佳。每关还有三项可独立获得的星级目标：完成运输、达到指定满意度、同时满足建设点数与最大排队限制；五日任务逐日评星并在关卡卡片汇总。路线首次贯通和送达 25% / 50% / 75% 会给出即时鼓励；胜利时播放彩片庆祝，结算星级依次揭晓并突出新获得的星和个人最佳。系统的“减少动态效果”设置会关闭动画但保留全部文字结果。
- 首次进入第一关会在地图上方按实际操作依次引导切换拖拽、连接全部同色建筑、选择住宅检查预计路线和开始运营；引导不覆盖 Canvas，也不会自动施工。道路等级、剪刀、路口控制和公交首次开放时分别给出短提示。可跳过引导，并从帮助弹窗重新打开；键盘、触摸、屏幕阅读器及减少动态效果设置均继续适用。
- 顶部可切换挑战与沙盒模式。挑战模式开始运营后规划锁定；沙盒沿用关卡预算但不限时间、不触发结算，运营中仍可安全地改路、剪断、升降级、调整道路引导和信号灯。公交设置须停止运营后修改。
- 「保存设计」按关卡将道路、等级、信号、公交线路与站点设置保存在当前浏览器；「读取设计」会替换当前方案并回到规划状态。除此之外，规划修改、切关和五日推进会自动保存最近关卡、挑战/沙盒模式及当前规划；刷新后可从顶部一键继续。五日自动进度包含日期、收入、预算、区域开放、建设支出和检查点，但不保存运行中的车辆或计时；运行时刷新会回到最近一次规划状态。
- 「清除自动进度」只删除上述最近状态，不会删除各关手动设计、星级、个人最佳或参考答案解锁。自动进度带独立版本并严格校验，损坏时整体回到新游戏，不会部分套用。
- 管理员可为普通关卡或多日任务的每一天保存完整参考答案（含道路连接、等级、引导、信号和公交）。玩家首次失败后按关卡或日期独立解锁“查看参考答案”，解锁状态保存在当前浏览器；载入答案不会自动运营，也不会改写多日进度、累计收入或预算。若当日实际预算不足以建设标准答案，系统会保持进度并拒绝载入。内置五日任务已为每天配置可通关答案。
- 玩家端运营倍速按钮按 **1× → 2× → 4× → 0.5×** 循环切换，并同步影响车辆、需求产生、公交上下客、信号灯和关卡倒计时；0.5× 便于观察路口，4× 便于快速验证规划。管理员预览在 4× 后额外提供 **∞×**，以固定 0.05 秒步长立即模拟到胜利或时限结束并直接显示结算，方便测试而不改变确定性结果。
- 「停止运营」保留当前设计，清空车辆、车上乘客、排队、成绩和计时，回到规划阶段以便重新尝试。
- 切到后台、打开帮助或重开/切关确认时自动暂停，需要手动继续。
- 界面以地图、目标、预算与计时为重点；顶部「切换关卡」和地图下方「设计存档」按需展开。电脑侧栏与手机地图下方均以标签按钮收纳任务、客流、连接和手记，默认显示任务。地图工作区会充分利用桌面宽度，常用工具与运营按钮位于地图上方，红绿灯阶段在宽屏下分栏展示；移动端检查器与公交设置作为底部抽屉，触摸规划时显示当前格坐标。屏幕阅读器可通过同步网格逐格读取地形、道路连接、负荷和选中状态，路线同时使用不同符号而非只靠颜色区分。

| 快捷键 | 操作 |
| --- | --- |
| `1` / `2` / `3` / `4` / `5` | 观察 / 选择 / 拖拽 / 剪刀 / 公交线 |
| `P` | 开始、暂停、继续 |
| 方向键 | 地图获得焦点后移动格子光标 |
| 空格 | 选择：选中当前格；拖拽、剪刀或公交线：设定起点，再用方向键延伸，空格提交或 Esc 结束 |
