# 慢行小城 · Make Way

原生 HTML / CSS / JavaScript 交通规划小游戏。7 个循序渐进且可自由选择的关卡，无构建步骤、无第三方依赖、无外部字体或图片请求。

## 本机游玩与网络访问

关卡从独立 JSON 文件加载，因此不能直接通过 `file://` 双击 `index.html`。需要 Node.js 18+，在项目目录启动本地服务：

```sh
node server.js
```

默认监听所有 IPv4 / IPv6 网卡的 **8180** 端口：

- 本机：<http://127.0.0.1:8180>
- 远程：`http://服务器IPv4:8180`
- IPv6：`http://[服务器IPv6]:8180`

自定义监听地址和端口：`HOST=0.0.0.0 PORT=9000 node server.js`。

**远程访问还需要防火墙放行、可路由的 IP，以及可能的路由器端口转发。监听所有网卡不等于已经可以从互联网访问。**

持久用户服务安装：

```sh
bash deploy/install-service.sh
```

详见 **[部署与网络说明](deploy/README.md)**。服务只开放游戏静态资源，不公开项目目录。各玩家在自己的浏览器内独立运行游戏，不共享道路、车辆或关卡状态；不是多人同步联机。

## 管理员面板

项目附带一个**需要密码**的管理员面板，用于创建关卡、编辑地图与数据库（关卡列表），并以 `levels.json` 持久化。面板绑定所有网卡的 **8080** 端口，凭密码进入，未登录无法读写。

直接启动：

```sh
ADMIN_PASSWORD=你的密码 node admin-server.js
```

然后访问 <http://127.0.0.1:8080>。默认密码为 `admin`，强烈建议通过 `ADMIN_PASSWORD` 环境变量（或项目根目录 `.env`）覆盖。面板加密校验密码，未登录无法读写；对外访问请务必设置强密码。

安装为持久用户服务（会读取 `ADMIN_PASSWORD` 或 `.env` 中的密码）：

```sh
bash deploy/install-admin-service.sh
```

面板支持：新建 / 复制 / 删除关卡，编辑元数据、预算、时长、目标与功能开关，增删路线（每条路线可含多个住宅与目的地，各自带输出速率/人数与可选输入上限），以及在地图上绘制水面、桥梁、树木、建筑和初始道路。保存会写入项目根目录的 `levels.json`。

**重要**：游戏服务在启动时把静态资源读入内存，因此修改 `levels.json` 后需重启游戏服务才能生效：

```sh
systemctl --user restart traffic-game.service
```

`built-in-levels.json` 是受版本控制的默认关卡数据库；`levels.json` 存在且合法时游戏自动优先加载它。管理员生成的 `levels.json` 已被 `.gitignore` 忽略，属于本地覆盖数据。JavaScript 只负责读取、校验和使用这些 JSON 数据，不再内嵌关卡定义。

## 七关渐进式小城

| 关卡 | 教学主题 | 出行组数 | 建设预算（点） | 时限 | 运输目标 |
| --- | --- | ---: | ---: | ---: | ---: |
| 01 晨光街区 | 基础连接 | 2 | 36 | 90 秒 | 100 人 |
| 02 街区改造 | 拆除与重建 | 1 | 27 | 60 秒 | 54 人 |
| 03 高层出行 | 客流与道路等级 | 3 | 60 | 65 秒 | 580 人 |
| 04 林间环城 | 环路集散 | 4 | 108 | 120 秒 | 200 人 |
| 05 交叉调度 | 交叉与信号灯 | 4（含 2 起点、2 目的地路线） | 110 | 95 秒 | 228 人 |
| 06 多点通勤 | 多起点与多目的地 | 1（2 起点、2 目的地） | 24 | 90 秒 | 110 人 |
| 07 都会早高峰 | 全功能综合规划 | 5（含 2 起点、2 目的地路线） | 150 | 100 秒 | 700 人 |

各课依次开放等级、负荷、剪刀和路况控件；第 4 关起路况与红绿灯可一并使用。所有关卡仍可自由选择。切换会重置本局；已有建设或正在运营时先弹出确认。胜利后可以前往下一关，最后一关可以重玩。

第 2～5 关预铺道路，费用计入总预算，剩余预算以界面为准；预铺道路可以改造或拆除。

- 第 1 关保留原布局与连接提示，只调整客流和目标。
- 第 2 关的绕路耗尽预算；先拆路退款，再修捷径。测试验证不改造无法通关。
- 第 3 关并列展示三种住宅与直达支路；按客流升级整条线路，避免用绕路长度制造假瓶颈。
- 第 4 关保留树林与建筑布局，预铺完整快速环路，只需补接支线；本关开始开放剪刀、路况检查与红绿灯，汇入口可保留自动避让，也可手动启用信号。
- 第 5 关只铺部分道路；补齐后形成六个交叉路口，包含转弯需求，并首次在高压力路网中混入多起点、多目的地路线。测试验证只连通不开灯、只开一盏灯均不能达到目标，多路口调度可通关。
- 第 6 关用同色的两座住宅和两个有限容量目的地，明确演示一条路线可包含多个起点与多个目的地，以及就近选择和满员改派规则。
- 第 7 关保留都会早高峰的地形、建筑与桥梁，并加入一组跨河的多起点、多目的地客流，重新平衡目标。

小桥课堂、河畔新城和旧剪断教学已移除，其关卡 ID 与设计存档不再受支持；核心默认场景改为晨光街区。仍保留的关卡 ID 不变，旧设计需通过当前地形、预算与建筑校验后才能读取。

### 运营前判断客流压力

地图每个住宅下方直接显示该住宅的本轮总输出与每秒客流，每个目的地标注其输入上限（不设上限则不显示）；侧栏提供完整的需求清单，含每个住宅与目的地的坐标、输出/输入。路线不再局限于“一点到一点”：一条路线可以包含多个住宅（各自拥有输出速率和总人数）与多个目的地（各自拥有可选输入上限）。车辆从某住宅出发后，按“可到达且输入未满的最近目的地”就近选择并锁定该目的地，途中再随路网重新寻路但不再变更目的地；某目的地达到输入上限后，后续车辆改派到次近的可达目的地。小房子为 **1 人/s**，大房子为 **4 人/s**，高层为 **6 人/s**，外形随规模变化。每车代表 1 位乘客；总人数包含尚未出发、排队、在途和已抵达者，不是当前队列长度。住宅角标仍表示当前排队人数。

以游戏实际使用的 `step(0.05)` 测量 13 格无路口单向直线，在持续饱和输入下，剔除前 30 秒启动期后，支路／干道／快速路的稳定抵达量约为 **2／5／6.67 人/s**。这是本模拟的实测值，不是速度乘容量，也不是含路口道路的保证值。小房子适合支路，大房子适合干道，高层适合快速路；合流、转弯、低等级出入口和信号配时都可能降低通达效率。测试同时验证持续 55 秒的高层需求无法由独立干道全部运完，更不能靠最低级道路完美运输。

需求从运营开始按固定间隔产生，达到标注总人数后停止新增。暂停冻结需求；停止运营或读取设计后重置需求与统计。关卡目标仍为时限内抵达人数，满意度不影响胜负。

## 道路等级、容量与信号灯

| 等级 | 每格建设费用 | 速度（格/秒） | 每方向车道数 | 每方向容量（辆） |
| --- | ---: | ---: | ---: | ---: |
| 支路 | 1 点 | 2.8 | 1 | 2 |
| 干道 | 2 点 | 4 | 2 | 4 |
| 快速路 | 3 点 | 5.2 | 3 | 6 |

路面宽度随车道数增加，所有等级的车辆长宽一致，不再缩小车辆以塞入更多车道。每格每条车道有前后两个位置，后车先进入后位，前位空闲才可前进；移动期间保留源位置和目标位置预约，禁止穿过前车。因此双向各一车道的支路每格共容纳 4 辆，干道与快速路双向总容量依次为 8、12 辆。

- 地图统一分为选择、拖拽、剪刀三种模式。拖拽模式只有在“从道路端点沿既有连接进入同等级道路”时判定为拆除，其余情况全部按建设处理：铺设空地、建立经过的格间连接，并把经过的既有道路刷新为起点等级。从空地开始建设支路；从建筑开始也视为道路起点，但建筑没有等级，向空地延伸固定使用支路。沿预览路线回拖可逐段取消，松手时整条规划才原子应用。相邻路面不会自动相连；建筑出口、桥梁与岸边都必须明确拖过。完整分类见游戏内 **[游戏指南](manual.html)**。
- **剪刀（3）**沿道路拖动，剪断经过的格间连接，保留两侧路面与等级，不返还预算；再沿断口拖动修路即可接回。
- 在选择模式点击已有道路会打开区域操作区，可分别点击升级或降级，也可设置红绿灯、查看路况或拆除。每次升降一个等级；升级支付差价，降级返还差价，拆除返还全部费用。桥梁只是允许在水面建设道路的地形：可以为空，也可以建设、升级、降级和拆除道路。
- 开始运营后规划会锁定，暂停时也只能选择区域查看路况；停止运营后才可继续建设、升降级、拆除、剪断或调整信号灯。
- 容量统计包含当前车辆和驶入预约；满载时车辆在上游等待，住宅也可能积压。各方向分别限额，并为同向车辆分配不同通行位置。不会因为拥堵直接判负，但排队会影响限时运输目标。
- 道路速度在混合等级交界处取较慢的一侧。寻路仍按最短格数，不是按旅行时间计算；升级短板、修建分流路线都能改善通行。
- 三岔与十字路口依据实际连接数识别（建筑出入口也计入分支），默认采用**自动避让**：到达路口前登记顺序、先到先行、逐车通过，进入与驶离路口时均按正常道路速度的 **35%** 行驶；出口满载时等待，其他具备通行条件的车辆可先行。该模式在繁忙路口效率较低。手动勾选「启用红绿灯」后，放行车辆按道路原速通过，不额外减速，但仍遵守红灯、冲突和容量限制。四阶段循环：**横向直行 → 横向左转 → 纵向直行 → 纵向左转**。默认每阶段绿灯 2 秒，阶段间有 0.25 秒直行/左转全红清空期；规划和暂停时信号计时也停止。
- 按车辆进入及离开路口的方向判断转向。**右转不受灯色限制**，但须避让可通行的直行/左转车辆及已经预约冲突区域的车辆；出口满载时仍等待。清空期也允许没有冲突的右转。
- 在规划阶段选择道路即可在区域操作区查看车道及前后位置容量；选择路口可将每阶段绿灯改为 **2 / 4 / 6 秒**，或关闭信号灯。运营期间仍可查看这些信息，但不能调整设置。
- 路口改为**四分区冲突预约**，不再整格仅限一车：对向直行、对向受保护左转及不冲突的右转可以并行。关闭信号灯则恢复 35% 速度、单车通行的自动避让。路口是通行空间，不按普通路段的前后车位排队；升级道路不会取消冲突约束。这是保守的简化冲突模型，不模拟全部真实车道转向组合。
- 「显示道路负荷」为道路加上绿 / 橙 / 红色边框，代表最忙方向的低负荷 / 接近满载 / 已满；路口显示四个冲突分区的预约率。红框不一定代表持续拥堵。路口不再使用小灯和文字标牌，而是在方格各进口一侧印上箭头线：直行与左转分别用绿线表示放行、红线表示等待；右转始终使用浅色弯箭头表示让行通行。只绘制实际存在的入口和出口，关闭信号后全部箭头变为浅色。车辆绘制在箭头线上方，侧栏仍提供完整阶段及倒计时说明。
- 七关均有预算内通关方案；参考方案按路线显式连接，并在繁忙路口手动启用信号灯。
- 设计存档使用 v2 格式，保存道路及格间连接，包括剪断的位置；v1 旧存档按原来的相邻自动连通规则迁移，保留原信号选择。

这是离散格子交通模型；“快速路”是游戏中的道路等级，并非真实交通法规中的封闭快速路。

## 操作

操作方法、车辆出行与交通模拟规则详见 **[游戏指南](manual.html)**。

- **选择模式（1）**：点击选择单格，拖动选择矩形区域。选区只在本模式显示。下方显示宽 × 高、道路总价、内容类型以及运营车流。道路提供分开的升级、降级和拆除按钮；住宅显示人口与输出流量；接收建筑显示容量；空地可建设单格支路；多格可批量升级、降级或拆除。
- **拖拽模式（2）**：从道路端点沿同级既有连接拖动才拆除，其他情况一律建设或按起点等级刷新所经道路。从建筑向空地拖动按支路建设。回拖取消当前预览，松手才一次性应用。
- **剪刀模式（3）**：剪断经过的道路连接，但保留路面与等级，不返还预算。
- 拖动经过的上下左右格间才相连，建筑也必须拖动连接。河流只能经过桥梁格，但桥面道路需要玩家建设，树林不可建设。
- 点击「开始运营」后，住宅按标注速率产生有限数量的车辆；多住宅/多目的地路线中，每辆车就近选择可达目的地上路，车辆沿当前最短路线行驶。
- 在本关时限内达到运输目标即胜利。住宅右上角实心气泡显示总人口，左下角显示出口流量，右下角“待”字气泡显示排队；目的地右上角描边气泡显示容量。
- 结算报告按每位已抵达居民从排队到到达的完整通勤时间分为轻松、舒适、尚可和漫长四档，并加权计算满意度；该分数仅用于战绩展示，不影响胜负或其他系统。
- 开始运营后规划锁定；暂停只会冻结车辆和计时，仍不能修改规划。
- 「保存设计」按关卡将道路、等级与信号设置保存在当前浏览器；「读取设计」会替换当前方案并回到规划状态。运营车辆、成绩与计时不属于设计存档。
- 2× 同时加快车辆与计时。
- 「停止运营」保留当前设计，清空车辆、排队、成绩和计时，回到规划阶段以便重新尝试。
- 切到后台、打开帮助或重开/切关确认时自动暂停，需要手动继续。

| 快捷键 | 操作 |
| --- | --- |
| `1` / `2` / `3` | 选择 / 拖拽 / 剪刀 |
| `P` | 开始、暂停、继续 |
| 方向键 | 地图获得焦点后移动格子光标 |
| 空格 | 选择：选中当前格；拖拽或剪刀：设定起点，再用方向键延伸，空格或 Esc 结束 |

## 开发与测试

```sh
node --test tests/*.test.js
node --check game.js
node --check server.js
```

测试覆盖原版逻辑、全部关卡的数据有效性与可通关性、独立状态、暂停与停止运营、设计存档校验和往返读取、等级差价、各级速度与容量、红灯等待、全红切换、路口冲突与占道保护，以及 HTTP 资源白名单、路径遍历防护、并发请求、HEAD 和缓存。

可选浏览器集成测试需要 Node.js 22+ 和 Chromium，无需 npm 依赖。先启动游戏服务，再将本机 Chromium 以 `--headless --remote-debugging-port=9333 --user-data-dir=/tmp/traffic-game-browser` 启动，执行 `node tests/browser-smoke.cjs`。它验证七关切换、教学工具解锁、预铺道路预算、拆路退款、设计保存/读取、道路升级、路口信号设置、结算报告和响应式布局；可通过 `GAME_URL` / `CDP_URL` 指定地址。调试端口只应在本机开放，测试后关闭调试浏览器。

```text
index.html                  中文界面、关卡选择、弹窗
manual.html                 操作方法、车辆出行与交通模拟规则的游戏指南
style.css                   响应式样式
built-in-levels.json         7 个默认关卡及渐进功能配置
levels.json                  管理员生成的可选本地覆盖数据
core.js                     DOM 无关的地图、容量与模拟引擎
game-results.js             结算页通勤满意度统计
game-effects.js             到达正向反馈粒子效果
game.js                     Canvas 绘图、输入与界面编排
server.js                   零依赖只读 HTTP 服务
admin-server.js              管理员面板服务（需密码）
admin.html / admin.css / admin.js  管理员面板界面

tests/browser-smoke.cjs      可选浏览器集成测试
```

没有账户、排行榜或服务器端游戏状态；设计存档仅保存在当前浏览器的 `localStorage` 中，每个关卡一个，不包含运营成绩。刷新会回到第一关，可通过「读取设计」恢复该关方案。车辆使用按方向限容、通行位置预约和路口分区冲突预约规则，并非真实交通工程仿真。
